1. Mục tiêu và phạm vi

TanStack Query giúp quản lý dữ liệu lấy từ server: trạng thái đang tải, lỗi, cache, làm mới dữ liệu, mutation và đồng bộ lại sau khi dữ liệu thay đổi. Thư viện không thay thế hoàn toàn useState, Zustand hoặc Context. Mỗi công cụ nên chịu trách nhiệm cho đúng loại state của nó.

Phạm vi áp dụng trong TalentHub

Tài liệu tập trung vào jobApi, danh sách việc làm, bộ lọc, phân trang và mutation cập nhật việc làm. Ví dụ dùng cấu trúc hiện tại trong src/modules/jobs và src/shared/api/axiosClient.js.

Kết quả mong đợi

Component chỉ mô tả query cần dùng. Logic gọi API, loading, error và cache được xử lý nhất quán mà không cần tự viết nhiều state phụ.

Nguyên tắc cốt lõi: TanStack Query quản lý dữ liệu server. State giao diện cục bộ như mở modal, nội dung biểu mẫu chưa gửi hoặc tab đang chọn vẫn nên nằm ở component hoặc store client state.

2. Phân biệt server state và client state

Trước khi thêm thư viện, cần xác định dữ liệu thuộc nhóm nào. Việc phân loại đúng giúp tránh đưa toàn bộ dữ liệu vào một store duy nhất.

Loại state Đặc điểm Công cụ phù hợp Ví dụ trong TalentHub
Server state Dữ liệu đến từ API, có cache, có thể cũ và cần đồng bộ lại. TanStack Query Danh sách việc làm, chi tiết việc làm, ứng viên từ backend
Client state Dữ liệu thuộc hành vi giao diện hoặc phiên làm việc của client. useState, Zustand, Context Trạng thái menu, user hiện tại, filter chưa gửi
Form state Giá trị nhập liệu, validation và trạng thái submit. useState hoặc thư viện form Biểu mẫu tạo việc làm, biểu mẫu đăng nhập

TanStack Query phối hợp với Zustand

Có thể dùng cả hai trong cùng ứng dụng. Ví dụ, Zustand giữ user đăng nhập và quyền truy cập; TanStack Query lấy danh sách việc làm. Query key chứa các tham số ảnh hưởng đến API, còn Zustand không cần giữ một bản sao của cùng dữ liệu đó.

3. Cài đặt thư viện

TalentHub đang dùng npm và React 19. Cài package tại thư mục gốc, nơi có package.json. 

npm install @tanstack/react-query

Devtools là phần tùy chọn, hữu ích khi kiểm tra query key, cache, trạng thái query và mutation trong môi trường phát triển. 

npm install -D @tanstack/react-query-devtools
  1. Kiểm tra package manager Dự án có package-lock.json, vì vậy dùng npm để cập nhật dependency và lock file thống nhất.
  2. Xác nhận phiên bản TanStack Query v5 sử dụng object syntax cho useQuery và useMutation. Không dùng các ví dụ v3 hoặc v4 có API cũ.
  3. Kiểm tra cài đặt Xác nhận package xuất hiện trong dependencies và chạy build trước khi tích hợp vào màn hình thật. 
npm run lint
npm run build
Ghi nhớ: TanStack Query cần một QueryClient được cung cấp qua QueryClientProvider. Nếu thiếu provider, các hook query sẽ không tìm thấy client trong React tree.

4. Cấu hình QueryClient

4.1. Tạo QueryClient dùng chung

Tạo một instance duy nhất ở ngoài component. Không tạo new QueryClient() trong thân component vì mỗi lần render có thể tạo client mới và làm mất cache.

src/app/query-client.js

import { QueryClient } from "@tanstack/react-query";

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30 * 1000,
      gcTime: 5 * 60 * 1000,
      retry: 1,
      refetchOnWindowFocus: false,
    },
  },
});
Option Ý nghĩa Giá trị đề xuất cho TalentHub
staleTime Khoảng thời gian dữ liệu được xem là còn mới. 30 giây, phù hợp dữ liệu danh sách có thể thay đổi thường xuyên.
gcTime Thời gian giữ cache không còn component sử dụng. 5 phút, giúp quay lại màn hình không phải tải lại ngay.
retry Số lần thử lại khi query lỗi. 1 lần, tránh chờ lâu trong môi trường phát triển.
refetchOnWindowFocus Tải lại query khi người dùng quay lại tab. Tắt ở bước đầu để hành vi dễ quan sát; có thể bật cho dữ liệu cần cập nhật liên tục.

4.2. Bọc ứng dụng bằng QueryClientProvider

src/main.jsx

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { QueryClientProvider } from "@tanstack/react-query";
import App from "./app/App.jsx";
import { queryClient } from "./app/query-client.js";
import "bootstrap/dist/css/bootstrap.min.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  </StrictMode>,
);

Nếu dự án vẫn đang dùng AuthsProvider, giữ provider đó bên trong QueryClientProvider. Sau khi chuyển auth sang Zustand, có thể bỏ AuthsProvider như tài liệu Zustand đã hướng dẫn.

4.3. Thêm Devtools trong môi trường phát triển

Devtools không cần thiết cho production. Có thể render có điều kiện để tránh thêm giao diện kiểm tra vào bản build chính thức. 

import { ReactQueryDevtools } from "@tanstack/react-query-devtools";

function AppProviders({ children }) {
  return (
    <QueryClientProvider client={queryClient}>
      {children}
      {import.meta.env.DEV && <ReactQueryDevtools initialIsOpen={false} />}
    </QueryClientProvider>
  );
}

5. Truy vấn dữ liệu với useQuery

5.1. Tách API function khỏi component

API function nên nằm trong module API hiện có. Component không nên chứa URL, query params và logic chuyển đổi response cùng lúc.

src/modules/jobs/api/job.api.js

import { axiosClient } from "../../../shared/api/axiosClient";

export const jobApi = {
  getJobs: async ({ index = 0, size = 10, filters = {} }) => {
    const response = await axiosClient.get("/api/v1/jobs", {
      params: {
        index,
        size,
        departmentId: filters.departmentId,
        title: filters.title,
        recruitmentMonth: filters.recruitmentMonth,
        recruitmentYear: filters.recruitmentYear,
      },
    });

    return response.data;
  },
};

Trong API hiện tại, jobApi.getJobs đang trả về Axios response. Có thể giữ cách đó nếu nhiều nơi đang dùng response.data; trong ví dụ dưới đây API được chuẩn hóa trả về trực tiếp response.data để query function dễ đọc hơn. Chỉ chọn một quy ước cho toàn module.

5.2. Query cơ bản cho danh sách việc làm

src/modules/jobs/pages/RecruitmentJobList.jsx

import { useQuery } from "@tanstack/react-query";
import { jobApi } from "../api/job.api";

const jobsQueryKey = ["jobs", "list"];

function RecruitmentJobList() {
  const { data, isPending, isError, error, isFetching } = useQuery({
    queryKey: jobsQueryKey,
    queryFn: () => jobApi.getJobs({ index: 0, size: 10 }),
  });

  if (isPending) {
    return <p>Đang tải danh sách việc làm...</p>;
  }

  if (isError) {
    return <p>Không thể tải dữ liệu: {error.message}</p>;
  }

  const jobs = data?.content ?? data ?? [];

  return (
    <section>
      {isFetching && <small>Đang cập nhật dữ liệu...</small>}
      {jobs.map((job) => (
        <article key={job.id}>{job.title}</article>
      ))}
    </section>
  );
}
Giá trị trả về Cách dùng trong giao diện
data Dữ liệu thành công từ API hoặc dữ liệu cache.
isPending Chưa có dữ liệu để hiển thị, dùng cho loading ban đầu.
isFetching Query đang gọi API, kể cả khi đã có dữ liệu cũ để hiển thị.
isError, error Trạng thái và đối tượng lỗi của lần gọi gần nhất.
Phân biệt loading: dùng isPending cho lần tải đầu tiên khi chưa có data. Dùng isFetching cho chỉ báo nhỏ khi query đang làm mới cache nhưng danh sách cũ vẫn có thể hiển thị.

6. Query key và cơ chế cache

Query key là định danh tuần tự hóa của dữ liệu trong cache. Khi tham số ảnh hưởng đến kết quả API thay đổi, tham số đó phải xuất hiện trong query key. Nếu không, các bộ lọc khác nhau có thể dùng nhầm cùng một cache.

6.1. Tạo query key factory

src/modules/jobs/queries/job.query-keys.js

export const jobKeys = {
  all: ["jobs"],

  lists: () => [...jobKeys.all, "list"],

  list: ({ index, size, filters }) => [
    ...jobKeys.lists(),
    { index, size, filters },
  ],

  detail: (jobId) => [...jobKeys.all, "detail", jobId],
};

Cách tổ chức này giúp đọc key nhất quán và invalidation theo tiền tố. Key của danh sách có thể chứa object vì TanStack Query xử lý key theo cấu trúc dữ liệu tuần tự hóa. Các giá trị trong key cần ổn định và có thể chuyển thành JSON.

6.2. Query có filter và phân trang

import { keepPreviousData, useQuery } from "@tanstack/react-query";
import { jobKeys } from "../queries/job.query-keys";

const params = {
  index: page,
  size,
  filters,
};

const query = useQuery({
  queryKey: jobKeys.list(params),
  queryFn: () => jobApi.getJobs(params),
  placeholderData: keepPreviousData,
});

Khi page hoặc filters đổi, key đổi và TanStack Query tạo hoặc dùng lại cache tương ứng. keepPreviousData giữ danh sách trước đó trong lúc trang mới đang tải, giúp giao diện không nhấp nháy về trạng thái trống.

6.3. Đọc và ghi cache khi cần

Chỉ dùng setQueryData khi đã chắc chắn shape dữ liệu mới khớp cache. Trong phần lớn trường hợp sau mutation, invalidation và refetch an toàn hơn.

7. Mutation và cập nhật dữ liệu

Query dùng để đọc dữ liệu. Mutation dùng cho thao tác tạo, cập nhật hoặc xóa dữ liệu trên server. Sau mutation thành công, cần làm cho các query liên quan biết rằng cache hiện tại có thể đã cũ.

7.1. Mutation cập nhật việc làm

src/modules/jobs/hooks/useUpdateJob.js

import {
  useMutation,
  useQueryClient,
} from "@tanstack/react-query";
import { jobApi } from "../api/job.api";
import { jobKeys } from "../queries/job.query-keys";

export function useUpdateJob() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: ({ id, data }) => jobApi.updateJob(id, data),

    onSuccess: (updatedJob, variables) => {
      queryClient.setQueryData(
        jobKeys.detail(variables.id),
        updatedJob,
      );

      queryClient.invalidateQueries({
        queryKey: jobKeys.lists(),
      });
    },
  });
}

setQueryData cập nhật nhanh cache chi tiết nếu response đã có dữ liệu đầy đủ. invalidateQueries đánh dấu các query danh sách là stale và refetch các query đang được hiển thị. Nếu API trả về response Axios, lấy response.data trước khi ghi vào cache.

7.2. Gọi mutation trong màn hình chỉnh sửa

function RecruitmentJobEdit({ jobId }) {
  const updateJob = useUpdateJob();

  const handleSubmit = async (formValues) => {
    await updateJob.mutateAsync({
      id: jobId,
      data: formValues,
    });
  };

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit" disabled={updateJob.isPending}>
        {updateJob.isPending ? "Đang lưu..." : "Lưu thay đổi"}
      </button>

      {updateJob.isError && (
        <p>Không thể lưu: {updateJob.error.message}</p>
      )}
    </form>
  );
}

7.3. Chu trình sau mutation

  1. Người dùng submit biểu mẫu.
  2. mutationFn gửi request tới API.
  3. Trong lúc chờ, khóa nút submit bằng isPending.
  4. Nếu thành công, cập nhật detail cache và invalidate list cache.
  5. Nếu lỗi, hiển thị thông báo và giữ dữ liệu biểu mẫu để người dùng sửa lại.
Không invalidate tất cả query mặc định: chỉ invalidate nhóm key liên quan đến mutation. Việc làm mới toàn bộ cache có thể tạo request thừa và làm trải nghiệm chậm hơn.

8. Phân trang và tìm kiếm trong TalentHub

8.1. Query hoàn chỉnh cho trang danh sách

State của bộ lọc chưa gửi và page đang chọn có thể nằm trong component. Khi bộ lọc thay đổi, đưa giá trị mới vào query key để query tự tải dữ liệu đúng.

src/modules/jobs/pages/RecruitmentJobList.jsx

import { useMemo, useState } from "react";
import {
  keepPreviousData,
  useQuery,
} from "@tanstack/react-query";
import { jobApi } from "../api/job.api";
import { jobKeys } from "../queries/job.query-keys";

const initialFilters = {
  title: "",
  departmentId: "",
  recruitmentMonth: "",
  recruitmentYear: "",
};

function RecruitmentJobList() {
  const [page, setPage] = useState(0);
  const [filters, setFilters] = useState(initialFilters);
  const size = 10;

  const params = useMemo(
    () => ({ index: page, size, filters }),
    [page, size, filters],
  );

  const query = useQuery({
    queryKey: jobKeys.list(params),
    queryFn: () => jobApi.getJobs(params),
    placeholderData: keepPreviousData,
  });

  const handleFilterChange = (event) => {
    setPage(0);
    setFilters((current) => ({
      ...current,
      [event.target.name]: event.target.value,
    }));
  };

  if (query.isPending) return <p>Đang tải...</p>;
  if (query.isError) return <p>{query.error.message}</p>;

  const jobs = query.data?.content ?? query.data ?? [];

  return (
    <>
      <input
        name="title"
        value={filters.title}
        onChange={handleFilterChange}
        placeholder="Tìm theo tên việc làm"
      />

      {query.isFetching && <small>Đang cập nhật...</small>}

      {jobs.map((job) => (
        <div key={job.id}>{job.title}</div>
      ))}

      <button
        type="button"
        disabled={page === 0 || query.isFetching}
        onClick={() => setPage((current) => current - 1)}
      >
        Trang trước
      </button>
      <button
        type="button"
        disabled={query.isPlaceholderData || query.isFetching}
        onClick={() => setPage((current) => current + 1)}
      >
        Trang sau
      </button>
    </>
  );
}

8.2. Khi nào nên debounce tìm kiếm

Nếu mỗi lần gõ ký tự đều tạo một query mới, API có thể nhận quá nhiều request. Với tìm kiếm theo tiêu đề, nên tách giá trị người dùng đang gõ khỏi giá trị đã debounce. Chỉ giá trị debounce mới được đưa vào query key. 

const [searchInput, setSearchInput] = useState("");
const [searchTerm, setSearchTerm] = useState("");

useEffect(() => {
  const timer = setTimeout(() => {
    setSearchTerm(searchInput);
  }, 300);

  return () => clearTimeout(timer);
}, [searchInput]);

const params = {
  index: page,
  size,
  filters: { ...filters, title: searchTerm },
};

Nếu TalentHub đã có cơ chế debounce dùng chung, tái sử dụng cơ chế đó thay vì tạo thêm hook trùng lặp trong từng trang.

9.4. Kiểm thử với MSW hoặc mock API

Khi có test tự động, mock request ở tầng network để kiểm tra hành vi của query và mutation. Không nên mock trực tiếp useQuery trong mọi test component, vì cách đó dễ bỏ qua lỗi query key, trạng thái loading và invalidation.

Ví dụ phạm vi kiểm thử

  • API trả về danh sách: giao diện hiển thị đúng số lượng việc làm.
  • API đang chờ: hiển thị loading và không hiển thị dữ liệu giả.
  • API lỗi: hiển thị thông báo và nút thử lại nếu có.
  • Mutation thành công: danh sách được làm mới.
  • Mutation thất bại: dữ liệu biểu mẫu vẫn còn để sửa.

10. Lỗi thường gặp

Hiện tượng Nguyên nhân Cách xử lý
Không tìm thấy QueryClient Component nằm ngoài QueryClientProvider. Kiểm tra provider ở main.jsx và prop client.
API gọi lặp không kiểm soát Query key chứa object bị tạo lại không đúng cách hoặc effect tự gọi refetch. Đưa toàn bộ tham số vào key ổn định và để query tự quản lý việc fetch.
Đổi filter nhưng dữ liệu không đổi Filter không nằm trong query key hoặc query function không đọc filter mới. Kiểm tra key và params truyền vào API.
Danh sách vẫn hiển thị dữ liệu cũ sau khi sửa Mutation thành công nhưng chưa invalidate query list. Gọi invalidateQueries với tiền tố đúng của list key.
Hiển thị spinner toàn trang khi chuyển page Chưa dùng placeholderData: keepPreviousData. Giữ data cũ trong lúc page mới đang fetch.
Cache bị mất sau mỗi render Tạo new QueryClient() trong component. Khởi tạo client ở module cấp cao, chỉ tạo một instance.
Ghi sai dữ liệu vào cache Response Axios chưa lấy response.data hoặc shape không khớp. Chuẩn hóa API response và kiểm tra shape trước khi dùng setQueryData.

  3. Chuyển RecruitmentJobList từ fetch thủ công sang useQuery.
  4. Chuẩn hóa query key cho list, detail, filter và phân trang.
  5. Chuyển mutation cập nhật việc làm sang useMutation.
  6. Thêm invalidation sau mutation và kiểm tra cache bằng Devtools.
  7. Mở rộng theo từng domain: candidates, departments và public jobs.

11.2. TanStack Query không thay thế mọi state

Không đưa mật khẩu, nội dung biểu mẫu chưa gửi, trạng thái modal hoặc trạng thái menu vào query cache. Không dùng query để thay thế hoàn toàn store auth. Hãy giữ ranh giới rõ giữa dữ liệu từ server và trạng thái điều khiển giao diện.
