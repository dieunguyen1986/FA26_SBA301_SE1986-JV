State Management với Zustand

Tài liệu nhập môn và triển khai thực tế cho ứng dụng React. Nội dung sử dụng chính luồng xác thực, phân quyền và danh sách việc làm của TalentHub làm ví dụ xuyên suốt.

1. Mục tiêu và phạm vi

Sau khi hoàn thành tài liệu, người học có thể cài đặt Zustand, tạo một store có state và action, đọc state bằng selector, lưu state vào localStorage và tổ chức store phù hợp với cấu trúc module của TalentHub.

Phạm vi áp dụng

Tài liệu dùng cho mã nguồn hiện tại của TalentHub: React 19, Vite, JavaScript, React Router và Axios. Các ví dụ dùng cú pháp JavaScript, không yêu cầu TypeScript.

Kết quả mong đợi

Phiên đăng nhập được dùng ở nhiều màn hình mà không cần truyền prop hoặc bọc thêm Context Provider. Dữ liệu phiên được khôi phục sau khi tải lại trang.

Nguyên tắc triển khai: chỉ đưa state có phạm vi dùng chung vào Zustand. State chỉ phục vụ một biểu mẫu hoặc một component vẫn nên dùng useState tại nơi sử dụng.

2. Nền tảng khái niệm

Zustand cung cấp một store dạng hook. Component lấy đúng phần dữ liệu cần dùng thông qua selector. Khi phần dữ liệu đó thay đổi, component được cập nhật; không cần tạo Context Provider riêng cho từng store.

Khái niệm Ý nghĩa Ví dụ trong TalentHub
State Dữ liệu mà giao diện cần đọc. user, jobs, filters
Action Hàm thay đổi state theo một nghiệp vụ cụ thể. login, logout, setFilters
Selector Hàm chọn một phần state trong component. useAuthStore((state) => state.user)
Middleware Lớp mở rộng hành vi của store. persist để lưu phiên vào localStorage

Zustand và Context hiện tại

TalentHub đang có AuthsProvider và AuthsContext. Cách này hoàn toàn hợp lệ với state dùng chung nhỏ. Khi state dùng chung tăng lên, việc chia store theo nghiệp vụ giúp logic, action và nơi lưu trữ rõ ràng hơn. Có thể chuyển từng phần một, không cần thay đổi toàn bộ ứng dụng trong một lần.

3. Cài đặt thư viện

Thực hiện các lệnh sau tại thư mục gốc của TalentHub, nơi có file package.json. 

npm install zustand
  1. Kiểm tra package manager Dự án hiện có package-lock.json, vì vậy dùng npm để package lock được cập nhật thống nhất.
  2. Kiểm tra cài đặt Mở package.json và xác nhận zustand xuất hiện trong mục dependencies. Không cần cài thêm thư viện React adapter.
  3. Chạy kiểm tra dự án Sau khi thêm store, chạy lệnh build và lint để phát hiện lỗi import hoặc lỗi cú pháp trước khi mở pull request. 
npm run lint
npm run build
Lưu ý: Zustand không yêu cầu bọc App bằng Provider. Store được import trực tiếp ở component cần sử dụng.

4. Tạo store đầu tiên

Nên đặt store trong vùng src/app/stores vì đây là state dùng chung cho nhiều module. Tên file dùng theo nghiệp vụ, không đặt tên chung như store.js.

src/app/stores/counter.store.js

import { create } from "zustand";

export const useCounterStore = create((set) => ({
  count: 0,

  increase: () =>
    set((state) => ({ count: state.count + 1 })),

  decrease: () =>
    set((state) => ({ count: state.count - 1 })),

  reset: () => set({ count: 0 }),
}));

src/shared/components/CounterExample.jsx

import { useCounterStore } from "../../app/stores/counter.store";

function CounterExample() {
  const count = useCounterStore((state) => state.count);
  const increase = useCounterStore((state) => state.increase);
  const reset = useCounterStore((state) => state.reset);

  return (
    <div>
      <p>Giá trị hiện tại: {count}</p>
      <button type="button" onClick={increase}>
        Tăng
      </button>
      <button type="button" onClick={reset}>
        Đặt lại
      </button>
    </div>
  );
}

export default CounterExample;

Cách đọc đoạn mã

  • create tạo một hook store có thể dùng trực tiếp trong React.
  • set cập nhật state. Với dữ liệu phụ thuộc state cũ, dùng dạng callback.
  • Selector chỉ lấy field cần dùng, giúp component không phụ thuộc vào toàn bộ store.
  • Action đặt cạnh state giúp quy tắc thay đổi dữ liệu nằm ở một nơi.

5. Áp dụng cho xác thực TalentHub

Đây là phần triển khai quan trọng nhất của tài liệu. Store thay thế vai trò của AuthsProvider: giữ user, đăng nhập, đăng xuất và khôi phục dữ liệu từ localStorage.

5.1. Tạo auth store

src/app/stores/auth.store.js

import { create } from "zustand";
import { createJSONStorage, persist } from "zustand/middleware";

export const useAuthStore = create(
  persist(
    (set) => ({
      user: null,

      login: (user) => set({ user }),

      logout: () => set({ user: null }),
    }),
    {
      name: "talenthub-auth",
      storage: createJSONStorage(() => localStorage),
      partialize: (state) => ({ user: state.user }),
    },
  ),
);
Cấu hình Vai trò
persist Lưu và khôi phục state giữa các lần tải lại trang.
name Tên key được tạo trong localStorage. Dùng tên có tiền tố dự án.
createJSONStorage Chọn localStorage và tự chuyển đổi dữ liệu sang JSON.
partialize Chỉ lưu user, tránh lưu các action hoặc state tạm thời không cần thiết.
Bảo mật: localStorage phù hợp cho bài tập và dữ liệu phiên của ứng dụng hiện tại. Với hệ thống production, cần tuân theo thiết kế xác thực của backend. Không lưu mật khẩu hoặc dữ liệu nhạy cảm vào store.

6. Áp dụng cho danh sách việc làm

Một store cho danh sách việc làm nên quản lý dữ liệu giao diện và trạng thái gọi API. Store không nên chứa JSX. Tầng API hiện tại vẫn giữ ở src/modules/jobs/api/job.api.js.

6.1. Tạo job store

src/modules/jobs/stores/job.store.js

import { create } from "zustand";
import { jobApi } from "../api/job.api";

const initialFilters = {
  title: "",
  departmentId: "",
  recruitmentMonth: "",
  recruitmentYear: "",
};

export const useJobStore = create((set, get) => ({
  jobs: [],
  total: 0,
  page: 0,
  size: 10,
  filters: initialFilters,
  loading: false,
  error: null,

  setFilters: (filters) =>
    set((state) => ({
      filters: { ...state.filters, ...filters },
      page: 0,
    })),

  setPage: (page) => set({ page }),

  fetchJobs: async () => {
    const { page, size, filters } = get();

    set({ loading: true, error: null });

    try {
      const response = await jobApi.getJobs({
        index: page,
        size,
        filters,
      });

      set({
        jobs: response.data?.content ?? response.data ?? [],
        total: response.data?.totalElements ?? 0,
        loading: false,
      });
    } catch (error) {
      set({
        loading: false,
        error: error?.response?.data?.message || error.message,
      });
    }
  },

  resetFilters: () =>
    set({ filters: initialFilters, page: 0 }),
}));

6.2. Sử dụng trong trang

src/modules/jobs/pages/RecruitmentJobList.jsx

import { useEffect } from "react";
import { useJobStore } from "../stores/job.store";

function RecruitmentJobList() {
  const jobs = useJobStore((state) => state.jobs);
  const loading = useJobStore((state) => state.loading);
  const error = useJobStore((state) => state.error);
  const fetchJobs = useJobStore((state) => state.fetchJobs);

  useEffect(() => {
    fetchJobs();
  }, [fetchJobs]);

  if (loading) return <p>Đang tải danh sách việc làm...</p>;
  if (error) return <p>Không thể tải dữ liệu: {error}</p>;

  return jobs.map((job) => (
    <div key={job.id}>{job.title}</div>
  ));
}
Về useEffect: action fetchJobs được định nghĩa ổn định khi store được tạo, vì vậy có thể dùng trong dependency array. Nếu API cần tải lại khi filter thay đổi, gọi fetchJobs sau khi cập nhật filter hoặc thiết kế một action kết hợp filter và fetch để tránh đọc state cũ.

6.3. Chọn nhiều field

Khi cần lấy nhiều field, cách rõ ràng nhất cho người mới là dùng nhiều selector. Việc này giúp nhìn thấy component đang phụ thuộc vào dữ liệu nào. 

const jobs = useJobStore((state) => state.jobs);
const filters = useJobStore((state) => state.filters);
const setFilters = useJobStore((state) => state.setFilters);

7.4. Kiểm tra store không cần render giao diện

Zustand cho phép đọc hoặc cập nhật store ngoài component. Chỉ dùng cách này cho các tích hợp rõ ràng như interceptor hoặc lớp điều phối. Component thông thường nên dùng hook selector để giữ luồng dữ liệu dễ theo dõi. 

import { useAuthStore } from "./auth.store";

const currentUser = useAuthStore.getState().user;
useAuthStore.getState().logout();

8. Lỗi thường gặp

Hiện tượng Nguyên nhân thường gặp Cách xử lý
Không tìm thấy module Zustand Chưa chạy lệnh cài đặt hoặc chạy sai thư mục. Chạy npm install zustand tại thư mục có package.json.
Trang không cập nhật sau khi set state Component đang đọc giá trị ngoài store hoặc selector không đúng. Đọc field bằng useStore((state) => state.field).
User mất sau khi reload Store chưa dùng persist hoặc key storage bị đổi. Kiểm tra middleware, tên key và dữ liệu trong localStorage.
API chạy lặp nhiều lần Effect có dependency không ổn định hoặc action bị tạo lại. Chọn action trực tiếp từ store và kiểm tra dependency array.
Dữ liệu cũ còn trong localStorage Schema user đã đổi nhưng key cũ vẫn tồn tại. Xóa key trong DevTools hoặc đổi tên storage khi thay đổi không tương thích.
